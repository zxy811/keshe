# 数字系统综合设计：从文件放置到显示结果

## 1. 先确认是哪一块板、哪一个系统

这一步决定后续教程是否适用，不要求你记住之前的配置。

1. 在宿主电脑按 Win+R，输入 winver，记录 Windows 版本。
2. 进入虚拟机；如果有 Windows 开始菜单，同样运行 winver；若是 Ubuntu，打开终端运行 `cat /etc/os-release`。不要为了运行旧 CCS 随意重装现有虚拟机。
3. 查看电路板丝印、处理器表面型号和现有 CCS Setup 配置。记录是否为 ICETEK-VC5509、TMS320VC5509/TMS320C5509，还是 TMS320F28335。
4. 查看 USB/JTAG 下载器标签，并在虚拟机设备管理器中记录设备名称、驱动是否正常。不要按猜测选择 XDS100 或 XDS510 驱动。
5. 本工程由原 Key.pjt 的 `CPUFamily=TMS320C55XX`、`cl55` 编译命令、ICETEK 外设地址和 C55x 运行库共同确认平台。文件名为 DSP28335 的手册不能证明两者兼容。

若板卡是 F28335，请在此停下目标下载操作。主机演示、Matlab 和便携算法仍可使用；板级按键 GPIO、时钟、内存映射、JTAG 配置以及目标工程都需基于 F28335 的实际板卡资料移植，不能只改工程的芯片名字。

先备份你已有的 C:\Lab0404-Key，不要直接覆盖唯一原件。新版工程移除了原有 Debug 下的旧编译产物，避免错把原 Sobel 的 key.out 当成新程序。original_v61.zip 完整保留你上传的代码。

Ubuntu 主机演示可以放在 `~/DSP_Course`。路径尽量使用英文、无空格目录，尤其是 CCS 3.3。不要把 Linux 编译出来的 .so 或 Windows .dll 当成 DSP 程序。

## 3. 虚拟机怎样配置

若原有 Windows XP 虚拟机已经安装 CCS 3.3 及匹配 C5509 的仿真器驱动，优先使用这个已知可用环境。现代 Python 工具运行在宿主 Windows 10/11 或现代 Ubuntu；Python 3.11 和当前依赖不支持 XP。

关闭虚拟机后可分配 2 核 CPU、2—4 GB 内存和足够磁盘空间（旧 XP 的实际内存限制以系统为准）。在 VMware 或 VirtualBox 中启用与你下载器驱动兼容的 USB 控制器；旧硬件常需 USB 2.0，但应以驱动说明为准。启动虚拟机后将下载器 USB 设备连接到客体系统。同一时间只让一个系统占用该 USB 设备，宿主 CCS 和客体 CCS 不要同时尝试连接。

共享一个专用目录，例如宿主 `C:\DSP_Shared`，虚拟机中映射为 `Z:\DSP_Shared` 或 `/media/sf_DSP_Shared`。共享的是源代码备份、图片 .dat 和导出结果，不是让两个 CCS 同时写同一工程。VirtualBox/VMware 的共享目录依赖对应增强工具及权限；若共享不可用，用受控的文件复制方式也可。

若虚拟机实际是 Ubuntu：可以运行本包的主机仿真和 Matlab/Octave，但原 CCS 3.3 Windows 工程及旧 Windows 下载器驱动不能直接按双击 exe 的方式使用。除非你已有经验证的 Linux C55x 工具链与仿真器方案，否则目标下载沿用 Windows 环境。

CCS 编译器/板卡驱动的软件许可由原提供方授权；本包未重新分发这些专有安装器。请使用学校或开发板厂商提供的匹配版本。

如果机器只有 python 命令、没有 py 启动器，可把 setup_host.bat 的 `py -3 -m venv .venv` 替换为相同版本的 `python -m venv .venv`。此处只影响主机辅助工具，不修改 DSP 算法。首次安装需要访问 PyPI；不要关闭 TLS 验证。

界面上按数字键 1—9 或点击按钮，两个上方窗口显示输入、处理结果，下方显示信号/频谱。界面标注 PC SIMULATION ONLY，实际调用编译为主机动态库的便携 C 源码，没有连接物理板。图片文件由主机 Pillow 加载，不是 DSP 直接读取电脑硬盘。

## 5. 为 C5509 构建真正可下载的程序

先确认第 1 节中的板型匹配，并安装 TI C55x 编译器。原工程使用 CCS 3.3 的 `C:\CCStudio_v3.3\C5500\cgtools\bin\cl55.exe`。若实际路径不同，通过环境变量明确指定：

```bat
cd /d C:\Lab0404-Key\v61
set "C55X_CGT=C:\CCStudio_v3.3\C5500\cgtools"
build_c55x.bat > build_local.log 2>&1
echo %ERRORLEVEL%
```

必须看到退出码 0，并检查 build_local.log。脚本先将独立 DIF 描述 `fft_dif_backend.c` 生成为 `generated\fft_dif_backend.asm`，随后将该 .asm 作为汇编源再编译链接。它不是手写汇编；如果老师要求手写，这一要求仍未满足，应另行补充，不要改报告措辞掩盖。

其余 C 文件和原板级代码共同链接为 `Debug\course_design.out`，映射文件为 `Debug\course_design.map`。原工程使用大存储模式 -ml，本脚本保持一致。新版把大数组和常量放到片内 SARAM，避免原 DARAM2 容量不够。没有把加载前必须初始化的数据放在尚未初始化的外部 SDRAM。

该构建命令在当前云机尚未运行成功，不能承诺无任何旧工具链兼容问题。如出现 `-fs` 选项不支持，应查看该版本 cl55 帮助中汇编输出目录选项，而不是伪造一个空 .asm。如果链接报告某区域空间不足，保留完整日志和 map，不要随便改内存地址。

构建脚本生成汇编后，也可以在 CCS 3.3 中打开 Key.pjt（保持上述固定位置），选择 Debug 重新构建。不要同时加入 fft_dif_backend.c 和它生成的 .asm，否则 fft_asm 重复定义。不要添加原 vectors.asm，它含原工程未使用的 Timer 引用；本工程沿用运行库的向量入口，并显式映射 vectors 段。

## 6. JTAG 下载与运行

1. 接好匹配板卡的电源和 JTAG，按板卡说明选择运行/仿真启动方式。
2. 打开 CCS Setup，选择实际下载器以及 C5509 目标配置。已有工作配置优先保留。
3. 启动 CCS，连接目标、执行匹配板卡的初始化 GEL/复位步骤。某些板卡依赖 GEL；不能把其他型号的 GEL 套上来。
4. 打开新版工程，使用 File → Load Program（菜单名以版本为准）加载新版 `Debug\course_design.out`。这是 JTAG 向目标 RAM 装入程序，不是 FLASH 固化。
5. 在 `app.c` 的 `App_ResultReady` 函数内 `gBusy = 0;` 语句处设置断点，点击 Run。首次应停在默认低通处理完成位置。
6. 在 Watch 中观察 gBusy、gResultSeq、gResultMode、gResultCutoffIndex、gResultSource、gLastKey、gError。函数入口断点可能在 gBusy 清零前停下；单步执行该行后 gBusy 应为 0，或在调用返回位置停下。
7. 查看 dbImage 和 dbTargetImage。要读新结果，先让程序继续 Run，按板上按键，等待处理完成的断点再停下，然后刷新窗口。停机期间物理按键不会被主循环实时处理。

本程序保留 PLL_Init(20)、SDRAM_init、InitCTR、GetKey 和原 ICETEK 的地址定义；不根据未知实物猜测频率或 GPIO。软件为按键触发的离线帧处理，没有 ADC/DAC 采集、中断实时调度或实时吞吐率保证。

## 7. 按键与参数如何理解

按 1 是 LPF；按 8 依次切换 1、2……10 kHz 后回到 1 kHz，初始参数是 4 kHz。按 2 是 BPF，按 3 是 BRF，按 8 循环选择 1—2 到 9—10 kHz。切换模式保留有效索引；从 LPF 10 kHz 切到带通/带阻时索引规整到 1—2 kHz。

这里的截止频率是理想分界的约 -6 dB 位置。设总过渡带宽 500 Hz，边缘两侧各留 250 Hz：例如 LPF 4 kHz 的通带截至 3.75 kHz，阻带从 4.25 kHz 开始；BPF 4—5 kHz 的通带为 4.25—4.75 kHz。不能用截止点约 -6 dB 的值来要求它已达到阻带衰减。

按 4 对源图第 40 行（从 0 起计）去中心后取 80 点、补零到 256 点，运行 C DIT FFT。按 5 运行独立 DIF 后端。输出 dbTargetImage 是频谱预览，不是逆变换重建图，也不是二维 FFT。精确复数结果在 gFFTReal/gFFTImag 中，每级缩放二分之一，总归一化为 1/256。

图片频率的单位是 cycles/pixel；用于课设 Hz 检验的 gSignalIn/gSignalOut 则是 fs=32 kHz 的独立一维测试信号。图像滤波沿每一行进行，采用镜像边界和居中卷积。这种离线图像演示没有给真实图像建立时间采样意义。

按 6 为 AM，按 7 为 DSB。一维消息频率 1 kHz、载波 8 kHz，AM 有明显 8 kHz 载波，DSB 主要保留 7 和 9 kHz 两个边带。图片窗口显示灰度行样本乘载波的结果；不是完整图像无线传输、解调或通信链路。

## 8. 自己的图片从哪里加载

电脑原图可以是 PNG、JPG 或 BMP，任意原始大小；转换工具会灰度化并缩放为 80×80。例：

```bat
cd /d C:\Lab0404-Key
.venv\Scripts\python.exe tools\image_tool.py convert C:\DSP_Shared\my_photo.jpg --out C:\DSP_Shared\user_image.dat
```

同时产生 user_image.png，用来确认缩放后的实际输入。DSP 不执行 fopen、不认识宿主的 C: 路径。真正加载流程是：原图 → 主机转换 → 6400 字 CCS .dat → 调试器写入 dbUserImage → 按 9 选择。

在 CCS 暂停目标，使用 Memory Load / File → Data → Load 等本版本提供的数据装载功能。指定目标符号 **dbUserImage** 的实际地址、数据页及 6400 个 16 位字（十六进制长度 0x1900）。.dat 头中的地址 0 只是占位，必须覆盖为该符号地址，绝不能向地址 0 装载图片。先在 Memory 窗口核对 dbUserImage 的符号地址和内容；不同编译结果地址会变化，不能抄旧 map 地址。

本机 C5509 的 unsigned char 是 16 位，每个数组元素占一个目标字，低 8 位灰度值为 0—255，不是把两个像素挤在一个字里。普通电脑的 unsigned char 则是 8 位；两种布局由各自工具正确处理。

导入后，在 Watch 将 gUserImageReady 设置为 1，再继续 Run 并按 9 循环到 gSource=2；也可暂停时设置 gSource=2、gCommand=1，再继续运行，由主循环消耗软件命令并处理。仅修改 dbImage 会被下次重新装载源图覆盖，所以用户图要写 dbUserImage。

## 9. 怎么在电脑刷新显示真实结果

方法 A：CCS 安装若包含 Image/Graph 显示工具，选择 Image 显示，起始符号 dbImage 或 dbTargetImage，宽高各 80、灰度、每像素一个 16 位目标字，显示范围 0—255。菜单和可选数据类型因版本/插件不同；如不能正确解释 16 位元素，请使用方法 B，不要按 8 位字节强行读取。

在 App_ResultReady 完成处暂停后 Refresh。按 Run → 物理按键 → 停在完成断点 → Refresh 的顺序重复。不要仅凭“端口开着”或运行指示灯就认定图像已更新；同时检查 gResultSeq 增加以及 gResultMode 对应。

方法 B（不依赖图像插件）：在 CCS 保存内存 dbImage、dbTargetImage，各 6400 个 16 位字，格式选择 TI CCS 十六进制文本 .dat（首行类似 `1651 1 ... ... 1900`）。保存为共享目录中的 input.dat、result.dat。主机执行：

```bat
.venv\Scripts\python.exe tools\viewer.py --board-dir C:\DSP_Shared
```

查看器每 750 ms 检查导出文件变化并刷新。这只自动读取新导出的文件，**不会自动从 JTAG 拉取数据**；每次板卡处理完成后仍需暂停并由 CCS 重新导出。运行中的数组可能尚在写入，不能在处理中途导出。先用临时文件保存完成后再覆盖结果文件可避免半写文件。

单张导出也可转换：

```bat
.venv\Scripts\python.exe tools\image_tool.py decode C:\DSP_Shared\result.dat --out C:\DSP_Shared\result.png
```

assets/example_board_exports 是主机生成的格式示例，并非真实板卡数据。不要把这些示例当成实测。

## 10. Matlab 仿真怎么执行

在现代系统中打开 MATLAB，切到 `C:\Lab0404-Key\matlab`，运行 `run_all`。脚本不依赖 Signal Processing Toolbox，会独立设计并检查全部 28 组滤波器、生成幅相波特图、FFT 和 AM/DSB 图以及 .mat 数据。

在 MATLAB 下，脚本输出到 matlab_output，包含 RUN_COMPLETED.txt，其中记录实际解释器版本和误差。这份标记只在脚本完整执行后产生。随包 results/figures 中图明确来自 Python，不能更改来源标签当成 MATLAB 图。本包另含 GNU Octave 9.4.0 实际执行得到的 30 张图，位于 matlab/octave_output；这证明兼容执行成功，但不代表 MATLAB 本体运行。将自己 MATLAB 运行得到的图替换报告中对应的仿真图后，写明本机版本和执行日期。

500 Hz 的全过渡带和 Q15 量化都纳入计算。全量系数见 results/filter_coefficients.csv，含每一抽头的浮点设计值、Q15 整数和实际定点值；tables.c 是板上实际使用的表。不要只提交一张滤波器示意图而漏掉系数。

## 12. 常见问题

* 按键没反应：先确认目标在 Run；查看 gLastKey 是否改变。若实际扫描码不是 1—9，读取原板卡键码定义，不要假设其他板卡也使用这些码。软件命令 gCommand 只能帮助定位按键硬件问题。
* 看不到新图：核对 gResultSeq 是否增加、断点是否在处理完成、地址是否来自新 map。模式切换保留输入，结果应变化。
* 图片变成噪声：核对 80×80、6400 个目标字、每像素一字、低 8 位为灰度。不要把 JPEG 文件字节直接装入像素数组。
* 带通图片灰色很多：输入可能主要是直流或所选通带外频率，灰度 128 表示去掉直流后的零值，不必然是错误。使用条纹或不同频率测试图确认。
* 缺 fft_asm 符号：先运行 build_c55x.bat 生成汇编，再检查项目只包含 generated/fft_dif_backend.asm。
* JTAG 连不上：记录下载器型号、USB 直通状态、电源和目标配置。C5509 与 F28335 驱动/初始化配置不能互换。
* 图像处理耗时：本程序是整帧离线演示，257 抽头卷积会占用时间；不要用 Delay(16) 推导每秒 60 帧。应使用真实目标计时测量后再讨论速度。

更多验收项目见 docs/硬件验收记录.md。报告中的待验证表格必须用真实运行结果填写。
